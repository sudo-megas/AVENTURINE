## 0. Ground rules

**Do not stop between phases.** Work from Phase A to Phase J in one continuous run. Do not pause to ask whether to continue, do not summarise and wait, do not ask for approval on design questions that `CORE.md` already answers. If `CORE.md` genuinely does not cover something, make the smallest reasonable decision, write it into `CORE.md`, note it in §13 of this file, and keep going.

**Release only when the application is actually finished.** Finished means: every checkbox below is ticked, the binary builds clean from a fresh clone, both packages install and launch, and `--doctor` reports correctly. A release that ships a half-working window is worse than no release.

**This file is living state.** After completing each task, edit this file:

- change `- [ ]` to `- [x]` on that task
- append one line to §13 with what happened, including anything that did not go as written here

The updated `B1.md` is committed along with the code for that task. Anyone opening the repository mid-run can see exactly where the build is.

**Commits.** One commit per task, not one per phase and not one at the end. Message format:

```text
A3: makefile builds an empty gtk window
```

Trailers, co-authorship lines and AI attribution are all permitted in this repository. Do not strip them.

**Verification is not optional.** Every phase ends with a verification block. Run it. If it fails, fix it before moving on rather than noting it as a known issue.

## 1. Environment

Written for Arch Linux with `fish` as the interactive shell. All command blocks are `bash`-compatible and safe to paste into either.

Install the toolchain:

```bash
sudo pacman -S --needed vala gtk4 glib2 pkgconf make gcc git base-devel github-cli
```

Confirm before starting:

```bash
valac --version
pkg-config --modversion gtk4
gh auth status
```

`valac` must be 0.56 or newer. `gtk4` must be 4.10 or newer, since `Gtk.FileDialog` is used in Phase E. If `gh` is not authenticated, run `gh auth login` now — Phase J cannot complete without it.

  ```makefile
  PREFIX ?= /usr

  test:

  .PHONY: all run test install clean
  ```

## 3. Phase B — colour mathematics

Build this before any UI. It is pure, testable, and everything else consumes it.

- [x] **B1.** `src/colour.vala` — the `Rgb` struct and the `Colour` class holding one colour, with lazily computed derived values.

- [x] **B2.** `src/convert.vala` — every conversion in `CORE.md` §8. Transcribe the matrices from the spec exactly; do not derive them from memory and do not round the coefficients.

- [x] **B3.** `tests/convert-test.vala` — assertions with known-good values. At minimum:

  | Input | Expectation |
  |---|---|
  | `#FFFFFF` | luminance `1.0`, OKLCH lightness `1.0` |
  | `#000000` | luminance `0.0` |
  | `#808080` | luminance ≈ `0.2159` |
  | `#FF0000` | LAB ≈ `53.24, 80.09, 67.20` at D65 |
  | round trip | sRGB → OKLCH → sRGB within `1e-6` for 20 sample colours |

  All must pass before Phase C starts.

- [x] **B4.** `src/contrast.vala` — ratios and the four WCAG verdicts per `CORE.md` §10.

- [x] **B5.** `src/ramp.vala` — the eleven-swatch tint and shade ramp per `CORE.md` §11, including the gamut clamp.

- [x] **B6.** `src/names.vala` — the 148 CSS named colours embedded as a static table, plus nearest-match in OKLab. Then attempt to vendor the 949-entry xkcd list into the same file. If it cannot be obtained, drop format row 14, record that in §13, and remove the row from `CORE.md` §9. Do not approximate it.

**Verify Phase B:**

```bash
make test
```

Every assertion passes. If `#808080` luminance is off, the gamma function is being applied to the wrong side — luminance uses **linearised** channels.

## 4. Phase C — the source ladder

- [x] **C1.** `src/source/colour-source.vala` — the interface exactly as written in `CORE.md` §5.

- [x] **C2.** `src/source/portal-source.vala` — the `PickColor` implementation per `CORE.md` §6.1.

  Three things break this if done in the wrong order, so do them in this order: build the request path from the connection's unique name, subscribe to the `Response` signal on that path, and only then call `PickColor`. Subscribing after the call loses the answer. Treat response code `1` as cancellation returning `null`, and `2` as an error.

- [x] **C3.** `src/source/image-source.vala` — open a file through `Gtk.FileDialog` or paste from `Gdk.Clipboard`, display it, read the clicked pixel through `GdkPixbuf`. Map the click coordinate through the widget's scale factor before indexing pixels, or picks will be wrong on the 1440p display.

- [x] **C4.** `SourceLadder` in `src/main.vala` — probe in order, cache the winner, honour `AVENTURINE_SOURCE`, re-probe when a pick fails.

- [x] **C5.** `src/doctor.vala` — the `--doctor` output exactly as shown in `CORE.md` §7.

**Verify Phase C:**

```bash

```

The portal rung must report `ok` on a session where a Screenshot backend implements `PickColor`. If it reports unavailable, that is a real finding, not a bug in the code: continue building, since the image rung still works, and note it in §13.

## 9. Phase H — continuous integration

- [ ] **H1.** `.github/workflows/build.yml` — three jobs. `build` compiles and runs `make test` on every push. `arch` builds the package in `archlinux:base-devel`. `debian` builds it in `debian:trixie`. Both package jobs run on tag pushes and upload their artifacts.

  ```yaml
  name: build
  on:
    push:
      branches: [main]
      tags: ['v*']
    pull_request:

  jobs:
    build:
      runs-on: ubuntu-latest
      container: archlinux:base-devel
      steps:
        - run: pacman -Syu --noconfirm vala gtk4 glib2 pkgconf git
        - uses: actions/checkout@v4
        - run: make
        - run: make test

    arch:
      needs: build
      if: startsWith(github.ref, 'refs/tags/')
      runs-on: ubuntu-latest
      container: archlinux:base-devel
      steps:
        - run: pacman -Syu --noconfirm vala gtk4 glib2 pkgconf git sudo
        - uses: actions/checkout@v4
        - run: |
            useradd -m builder
            chown -R builder .
            sudo -u builder bash -c 'cd packaging/arch && makepkg -f --nodeps'
        - uses: actions/upload-artifact@v4
          with:
            name: arch-package
            path: packaging/arch/*.pkg.tar.zst

    debian:
      needs: build
      if: startsWith(github.ref, 'refs/tags/')
      runs-on: ubuntu-latest
      container: debian:trixie
      steps:
        - run: |
            apt-get update
            apt-get install -y valac libgtk-4-dev pkg-config make gcc dpkg-dev git
        - uses: actions/checkout@v4
        - run: make
        - run: bash packaging/debian/rules
        - uses: actions/upload-artifact@v4
          with:
            name: debian-package
            path: '*.deb'
  ```

- [ ] **H2.** Push and confirm the `build` job goes green before continuing.


## 12. Rollback

If the release is wrong and has to be withdrawn:

```bash
gh release delete v1.0 --yes
git push --delete origin v1.0
git tag -d v1.0
```

To undo the last commit while keeping the work:

```bash
git reset --soft HEAD~1
```

To abandon a broken phase entirely and return to the last good commit:

```bash
git log --oneline -10
git reset --hard <commit-sha-of-last-good-task>
```

That last one discards uncommitted work, which is why every task commits.
